## 1. Executive summary

The picture from two weeks ago holds, with the documentation half of it substantially retired. The load-bearing achievement is unchanged and still enforced: every JSON definition under `src/main/resources/draco` regenerates its own Scala byte-for-byte (`DracoGenTest`), emits its own `.drake` surface (`DrakeGenTest`), and parses back to a JSON that survives a normalized round-trip (`DrakeParseTest`). Gate 2 got strictly stronger on 08-25 — it no longer normalizes reference packages away, so what used to be a measured loss is now a hard failure (`DrakeParseTest.scala:139-146`, `DrakeCLI.scala:123-126`). Both #51 slices were simulated over the whole corpus before compiling, and both reported zero differences; that method is now the norm for metamodel work and is the strongest process improvement in the period.

The gap between tree and prose has closed at the top and persists one level down. `DRACO.md` — the file every session auto-loads — is now correct: five aspects, eleven `TypeElement` kinds on `Primal[Json]`, the `TypeLoader`/`DefinitionPath` path, six-way dispatch, the mods file list, all verified at source. But `DRACO.md:229` still tells sessions the CHANGELOG stops at alpha.5, a line that was false in the very commit that wrote it; `DRACO.md:170` and `README.md:196` both call `drake.dlt` "current and authoritative" while all five of the old review's `.dlt` staleness items survive verbatim, including a line 2 that says the parser does not exist yet. `AGENTS.md` is still the pre-rewrite `DRACO.md`, frozen at 2026-06-23 — the exact document the rewrite warns about. Three versions are in play at once: `build.sbt` alpha.6, `README.md:459` alpha.5, `CLI.scala:18` alpha.1.

Beneath that, the defect list is nearly static. Recommendation 2 — "close the concrete bugs, one session" — was not attempted, and two of those bugs are now worse than they were. `ActorAspect.isEmpty` still ignores `messageType` (`ActorAspect.scala:51`) while the encoder elides the aspect on `isEmpty` (`TypeDefinition.scala:22`); after the 08-26 migration `messageType` is the *sole* carrier of an actor's message type, so that asymmetry has gone from a round-trip curiosity to the thing standing between the corpus and a silent data loss. The Generator is still not a pure function of its input. Four tests still write into tracked source. CI is still tag-only, and the action bumps that repaired it have never executed, because the only tag predates them.

The single most important technical finding is new and is not draco's code. `SubtypeFactVisibilityTest` (new at HEAD) shows that Evrete honours inheritance one level at a time but, when an ancestor and a descendant are declared in the same knowledge, resolves neither and **skips the insert**: the fact never reaches working memory, every rule goes quiet, nothing throws, and the only trace is a `java.util.logging` warning. The corpus is safe today by shape rather than by design. That belongs in `DomainBuilder.validate` as a rule, not in a gotchas list.

My recommended order of work is in §7. The short version: encode the co-declaration constraint as a validation rule, then finally take the §4 bug list (it has waited two weeks and grown teeth), then make parse output honest, then #51's remaining edges.

## 2. What is actually built (as-is architecture)

`README.md` and `DRACO.md` §3 now describe this accurately; this section is retained as a second, independently-verified statement, with the corrections the 08-15 version needed.

**Type system.** `DracoType` is a one-member trait (`DracoType.scala:3-5`). `TypeDefinition extends Aspects { val typeName }` (`TypeDefinition.scala:6-8`), and `Aspects` is five slots (`Aspects.scala:3-9`): `dracoAspect` (nine fields — superDomain, modules, extensible, derivation, elements, factory, globalElements, source, target, `DracoAspect.scala:7-15`), `domainAspect` (typeName self-loop or container pointer, elementTypeNames), `ruleAspect` (pattern, action), `actorAspect` (`message, messageType, signal, start`, `ActorAspect.scala:6-11`), `codecAspect` (discriminator). *Correction to the 08-15 text:* `TypeElement` (`TypeElement.scala:6-12`) has one direct subtype, the intermediate `sealed trait BodyElement` (`:132`); the eleven kinds — Fixed, Mutable, Dynamic, Parameter, Monadic, Pattern, Action, Condition, Variable, Factory, Local (`:144, 174, 206, 242, 272, 294, 321, 347, 371, 398, 428`) — extend *that*. All are `Primal[Json]`, so `value` is a JSON node: a host-opaque string or a single-key `{op: [operands]}` tree. `Domain[T] extends DomainType` (`Domain.scala:3`); `Actor[T] extends ExtensibleBehavior[T] with ActorType` (`Actor.scala:5`).

**Companion convention.** Unchanged: `object X extends App with DracoType { override lazy val typeDefinition = TypeLoader.loadType(TypeName(...)); lazy val dracoType = Type[X](typeDefinition); … }` plus derived codec, `apply`, `Null`. *Correction to the count:* `src/main/scala/draco` carries **81** such companions across 69 files (`TypeElement.scala` alone holds 13); the old "53" counted the flat directory only. The lazy-val discipline holds throughout, with the two exceptions in §4 row 8.

**Loading.** `TypeLoader.loadType → tryLoad → loadFromResource → DefinitionPath.default.source(resourcePath) → readDefinition` (`TypeLoader.scala:14-18`). `DefinitionPath.hostRoots` splits `java.class.path` (`DefinitionPath.scala:25`); `sources` probes every root with `openStream()` (`:6`); more than one hit is a hard `sys.error` (`:8`). A missing or unparseable JSON yields a typeName-only stub.

`rooted` was rewritten by `324556c` and now reads (`TypeLoader.scala:17`): a definition is left alone if any derivation entry carries a **non-empty package**, or if it is `draco.DracoType` itself; otherwise `draco.DracoType` is **appended** (`:+`) rather than substituted. Two changes from the old predicate (`derivation.nonEmpty`, replace): the guard distinguishes a parent that roots the type from one that does not, and the injection composes. The whole change exists for one file — `Dictionary`, whose sole parent `Map` is the corpus's only package-less derivation.

**Generator dispatch** (`Generator.scala:1660-1745`). Entry normalizes with `targetTypes(TypeLoader.rooted(_td))` at `:1668`. Order: `roleAspectCount >= 2` → `composedGlobal` (`:1669`); `isRule` → `ruleGlobal` (`:1679`); `hasActorBehavior` → `actorGlobal` (`:1692`); `isDomain` → `domainGlobal` (`:1701`); `isObjectOnly` → `objectGlobal` (`:1710`); `isLeaf || isActor` → `typeGlobal` (`:1716`); else `IllegalStateException` (`:1738`). Six emitting branches — the last arm is now guarded rather than a bare `else`. *Correction:* the `{K,V}` → `Map[K,V]` rewrite is `scalaTypeExpression` (`:1562-1594`) and applies to **valueTypes only**; `targetTypes` copies `_derivation` verbatim (`:1638`), and `Dictionary.scala:3`'s `Map[K, V]` parent comes from `parameterizedName` (`:171-175`).

**Codec derivation.** `codecDeclaration` (`Generator.scala:834-865`): discriminated-parent walk → `subtypeCodecDeclaration`; `modules.nonEmpty` → discriminated union; else "simple" iff own elements ∧ factory params ⊆ (own ∪ inherited) ∧ no uncodecable param. Still *inferred* structurally. Re-checked programmatically over all 132 JSON: **not one carries a top-level `codecAspect`.** The string occurs three times corpus-wide — two field declarations and one value string.

**DRAKE.** `Drake.scala` is now 1090 lines (was 1019), with `Expression.scala` (83), `DrakeCLI.scala` (144, `emit | parse | check` at `:139-141`, still no `bin/` wrapper) and `SourceContract.scala` (81). The grammar is as before — header `type Name(T…) [from ref…]`, keyword sections, `domain`/`rule`/`actor` blocks, `codec` rejected on both sides (`:420`, `:1062`) — plus two additions:

- **Foreign derivation by operator** (`324556c`): `reference` trifurcates (`:439-442`) — empty package → `foreignReference` (`:294-322`, spelling `Map`→`{K, V}`, `Set`→`{T}`, `Seq`→`[T]`), own package → bare, else qualified. The universal root is elided when reconstructable (`rootRestored`, `:450-452`). Parser inverse at `:839-873`, `:1071`.
- **Package-carrying `messageType`** (`05b14bd`): emit `typeRef` → `reference` (`:546`), parse `parseRef` → `takeQualifiedRef` (`:1057`) then `resolved` (`:1088`). `aerial/Consumer.drake:4` now reads `messageType draco format json JSON`.
  The application surface is still the only place the parser builds trees; every other value slot returns a raw span (`:660-667`, `:679-684`).

**Outer layers.** `draco.generator.Generator[L]` is still a one-field trait with no implementor; `draco.scalatarget.ScalaTarget` aliases the mods engine; `draco.rete.*` are four marker traits; `draco.dreams` + `dreams/orion` are eight empty traits; `format.{json,xml}` — `JSON`/`Value` real, `XML` a stub. `src/mods/scala/domains/` is 7 dirs / 55 files. `src/mods/scala/draco/format/yaml/Yaml.scala` is still the ch. 56 leftover. `src/main/scala/org/nexonix/**` (9 files, 354 lines) is still referenced by nothing.

## 3. Design assessment

### 3.0 The finding I'd now rank first: co-declaration drops the fact

`SubtypeFactVisibilityTest` (`src/test/scala/domains/world/`, new in `0af56fd`) inserts one `FixReport` (`FixReport <: Marine <: World`, and `<: JSON`) and asks which declared types see it. Solo — one knowledge, one rule — all four levels fire. Declared together in one knowledge, **none** fires: `DefaultTypeResolver` reports ambiguity, `AbstractRuleSessionOps` skips the insert, the fact never reaches working memory, nothing throws, and the only trace is a `java.util.logging` warning.

Inheritance itself is honoured — a rule declared two levels up sees the fact. The failure is specifically co-declaration of an ancestor beside a descendant. The corpus is safe today **by shape, not by design**: each medium's session declares siblings (`PositionReport` + `FlightIntent`), and draco's validation session a deliberately disjoint taxonomy (`Problem` / `TypeDefinition` / `DomainType`). Nothing currently declares an ancestor beside a descendant. The moment a user domain does, their rules go quiet with no diagnostic.

Why this outranks the old §3.2: it is a *soundness* hole in the engine draco ships to users, the failure mode is silence rather than error, and nothing in the metamodel encodes the constraint. It is recorded in `DRACO.md:235-243` and `CHANGELOG.md:35` — prose, in a gotchas list, guarding a property that no gate checks. It belongs in `DomainBuilder.validate` as a fifth validation rule: *no two members of one domain's rule set may declare fact types on a common derivation chain.* That is a mechanical check over data draco already has, and it is the natural home for it given that the framework already validates its own foundation through the rules it ships.

It also reframes #63. The 08-27 record corrects the issue's own premise: the actor dispatch is not for *routing* — the engine routes siblings correctly on its own — it is for **converting hierarchy into siblings**, so that the one thing the engine cannot do safely is never asked of it. That is a good and clarifying finding, and it should be written into #63's body rather than left in a record.

### 3.1 Strengths worth naming

Everything named on 08-15 still stands, and three things can be added. **Measurement before compilation is now the house method for metamodel work:** both #51 slices simulated the full corpus round-trip before a line was compiled — 91 headers and 98 references on 08-25, eleven message types plus 91 definitions on 08-26, "zero differences either way" both times. **Gate 2 became a gate.** The 08-25 record states the distinction exactly: "a gate that measures a loss and a gate that forbids it are different gates; this is the second one now" — the `namePackage` normalization is gone from both `DrakeParseTest.surfaceCarried` and `DrakeCLI check`. And **the records now predict their own report-only output** before the run (08-25, 08-26, 08-27), which makes a report-only regression falsifiable for the first time; the 08-27 record goes further and chains `sbt test &&` into the commit block, so the gate is mechanically enforcing rather than advisory.

The alpha.6 release notes deserve their own mention: a Known Limitations section that says plainly that Scala is the only realized target, that `Drake.parse` is a measurement tool rather than an authoring path, that there is no shell wrapper for `DrakeCLI`, and that the metamodel is **not** frozen. That is what makes an alpha honest.

### 3.2 Parsed drake is not generation-safe — still true, and now sharper

The demotion is intact. `Drake.leafValue` (`:679-684`) recovers trees only for `""`, `"[]"` and `"{}"`; everything else is `Json.fromString(other)`. `Generator.expression` (`:86`) passes the string through verbatim into Scala. **There is still no lint and no warning** — the only `System.err` in either file is `DrakeCLI`'s usage text. `format/json/Value.drake:12-13` still carry `\e a -> …` and `if … then … else`.

What changed is that the hypothetical became a corpus. `src/test/resources/scenario/` is 22 `.drake` files with **no JSON twins** — precisely the drake-first authoring path the old review said would break the round-trip. `scenario/ash/RootInterface.drake:8` carries a Scala `match` on one line as host-opaque text. The repo says this itself, in both the test and the record: parsing it proves nothing, because drake can store the text, cannot read it, and cannot project it to any other target. And `ScenarioDrakeTest` is report-only (`:101`, `succeed`) with a CWD-relative path (`:41`) and an `assume` (`:57`), so a wrong working directory cancels rather than fails.

So the finding is unchanged in substance and worse in exposure: the round-trip is now demonstrably not the authoring path, on a corpus that exists. The lint — "no host-opaque string may contain a drake-form token" — is still the smallest thing that closes the *silent* half, and it is still not written.

`DrakeParseTest` names four loss buckets (`:293-297`): empty-collection spelling, expression form (string vs tree), reference package, and unaccounted. The `reference package` bucket is now structurally zero — a residual would fail gate 2 rather than be normalized away. Per the 08-25 record the residual is 15 fields: 12 expression-form (#61), 3 empty-collection (#55). A second exclusion has appeared alongside `authoredAhead`: `inlineTupleArgument = Set("domains/terrestrial/Output.json")` (`DrakeParseTest.scala:207`), an inline tuple whose interior application is lexically invisible — a fresh instance of this finding, not of the presence model.

### 3.3 The Generator is not a pure function of its input — unchanged

`chainHits` (`:51-64`, with `catch { case _: Throwable => false }` at `:61`), `loadDracoType` (`:111-120`), `inheritedElementNames` (`:615-628`) and `actorKnowledge` (`:1169-1184`) all still consult the classpath during emission; `actorKnowledge` loads every `elementTypeNames` entry just to test for a rule aspect. `grep -n "cache\|memo"` over `Generator.scala`: no hits. Nothing moved. The fix is the same: extend the existing `familyContext` into a loaded-family/`DefinitionPath` context and drop the implicit lookups.

### 3.4 Two competing notions of actor-ness — narrowed to a residue, and half-closed

`05b14bd` resolved this in the corpus rather than in the code. `hasActorBehavior` (`:1119`) still drives dispatch (`:1692`) and `roleAspectCount` (`:1381`). But `Generator.isActor` (`:1360`) — derivation reaches `ActorType`/`ExtensibleBehavior` — now matches **exactly one definition in 132**: `src/main/resources/draco/Actor.json`, the base trait itself. Eleven definitions carry `actorAspect.messageType` (`Draco.json` plus the ten mods actors), and every one of them also carries a body, so `hasActorBehavior` is true for all. `AssemblyValidator` inverted: the aspect is now the source of truth, the derivation a documented fallback (`AssemblyValidator.scala:29-38`) — the old §4 row 7 first half is closed.

Three things remain, and two are new:

- `isActor` is dead weight in the dispatch that still buys Pekko imports and `isLeaf` for one type. It should be deleted, not left as a second and now-false predicate.
- `domains/world/Consumer.json` and `Provider.json` are still the exception, and are now doubly odd: they carry an `Actor(World)` derivation and **no `actorAspect` at all**, so both notions are false for them and they take the plain-leaf branch. The 08-26 record makes the case that they are not debt but the worked example the dispatch grammar has to reproduce — an actor typed high in the tree, dispatching on a subtype, transforming and forwarding. I agree with keeping them, and would only add that `DRACO.md:189-191` lists "the `Actor(T)` derivation on an actor" under **Retired — do not reintroduce**, which is now overstated by exactly these two files.
- `AssemblyValidator.scala:37` compares via `TypeName.namePath`, which drops `typeParameters` (`TypeName.scala:43`), while `Generator.scala:1139` uses `spelled`/`parameterizedName`, which keeps them. A parameterized message type would produce a spurious "expects ActorRef[…]" mismatch. No corpus case yet; the doc comment at `AssemblyValidator.scala:32` claiming the two agree is wrong.
### 3.5 Codec inferred-in-code, declared-in-principle — no movement, now four and a half months

Zero top-level `codecAspect` in 132 JSON. Both drake sides still reject the keyword. `DrakeGenTest.authoredAhead` is unchanged (`:29-32`): `draco/BodyElement.json` and `draco/ActorAspect.json`, the same pair excluded from `DrakeParseTest` gate 1 (`:115`). The presence model (present-empty `rule`/`actor` still eliding to absent) is likewise untouched. Both deferrals now carry an extra fortnight and neither has a date. The §8 question stands unanswered.

### 3.6 Core vs mods split has inverted — holds, with one clause restated

`TypeDictionary.apply` still builds hollow members (`TypeDictionary.scala:15` — name only, no load); `DomainBuilder.define` (`:52-69`) is still the mods-side workaround that loads each member; `DomainBuilder.validate` (`:94-122`) still runs the three checks. The engine is nine hand-written files in `src/mods/scala/draco/`.

*Restatement of the old claim:* `Generated.scala` and `Codec.scala` do not literally trip `validate`, because it fires only on **declared** members and neither is in `Draco.json`'s `elementTypeNames`. What they violate is the ch. 43 north star — `src/main` Scala with no JSON backing at all. The invariant is intact; the principle is not. `mods/README.md:62` still describes `Generator.loadType` as "the production API" while `DRACO.md:140` says `TypeLoader` owns it — a soft conflict, true only because `Generator.scala:45` is a one-line delegate.

### 3.7 DRAKE robustness — mostly holds; three clauses corrected

I ported the lexer (`Drake.scala:599-634`) and ran the cases rather than reasoning about them.

- **`par =x`** — confirmed and silent. `=x` is not the reserved `=`, so `span` swallows `=x 3` as a positional argument's leaf value. Named argument lost, no error.
- **`[cursor`** — confirmed and worse than stated. `blockBracket` requires `[` followed by whitespace (`:606`); glued, the lexer enters depth-tracking and **runs past newlines to the next `]` or EOF**, consuming subsequent members whole.
- **`mut{T}`** — *corrected.* The gluing happens, but the token is not a member keyword, so it reaches the top-level `case other => sys.error("unexpected section")` (`:1063`). It now errors — unhelpfully and without position — rather than parsing to something else.
- **`Iterator( (K,V) )`** — *narrowed.* The glued form is one token, which is what the emitter wants. The hazard is the *spaced* form, and only where a single token is expected; in a leaf value slot `span` recovers the raw substring (`:667`).
- **No line/column** — confirmed, and now stated as deliberate at `:596-597` ("drake is whitespace-insignificant").
- **`take` at EOF** — confirmed (`:654`, unchecked `Vector` index). The thrown type is `IndexOutOfBoundsException`, not `ArrayIndexOutOfBounds`.
- **Duplicate sections** — confirmed (every section assigns a `var`, `:1030-1061`). *Corrected:* **unknown** sections now error (`:1063`); the old "unknown or duplicate overwrite silently" was half wrong.
- **Latent Parameter-default ambiguity** — still open, unchanged. `parLines` brackets an application-valued argument (`:178-190`, the #60 fix); `leafLines` does not (`:352-357`). No corpus type hits it.
- **Three renderers** — confirmed, and the `||` drift is unchanged: `Drake.expression:100` and `Generator.expression:100` both have it; `SourceContract.scala:51` still does not, so the third renderer will `sys.error` on `SelfDeclaration.json:22`.
